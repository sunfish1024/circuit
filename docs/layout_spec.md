# 固定部品のレイアウトとガイド線（problem-writer 向け仕様）

問題を開いたときにボードに置かれる固定部品（`fixedComponents`）の**位置・向き**と、
固定部品どうしの**つながりの表示（ガイド線）**の決まりです。
計算は `src/ui/geometry.js`（画面とツールで共通）、検査は `node tools/check_layout.mjs` です。

## 1. どこに書くか（既存の問題はそのまま使える）

部品の位置と向きは、これまでどおり **`fixedComponents[].position` と `rotation`** に書きます。
これが layout の本体です。追加で、問題 JSON の最上位に省略可能な `layout` を置けます。

```json
"fixedComponents": [
  { "id": "V1", "type": "V_DC", "params": { "V": 5 }, "connect": ["vin", "gnd"],
    "locked": true, "rotation": 90, "position": { "x": 80, "y": 200 } },
  { "id": "R1", "type": "R", "params": { "R": 1000 }, "connect": ["vin", "out"],
    "locked": true, "position": { "x": 240, "y": 100 } },
  { "id": "TP1", "type": "TP", "params": {}, "connect": ["out"],
    "locked": true, "position": { "x": 420, "y": 40 } }
],
"layout": {
  "guides": true,
  "groundSymbols": true,
  "routes": [ { "net": "out", "points": [[312, 114.5], [456, 114.5], [456, 81]] } ]
}
```

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `layout.guides` | bool | `true` | `false` でガイド線も自動 GND 記号も描かない |
| `layout.groundSymbols` | bool | `true` | `false` で gnd ネットもほかのネットと同じく線で結ぶ（GND 記号は描かない） |
| `layout.routes` | 配列 | なし | 手動の経路。`net` を書いたネットは自動配線せず、`points` の折れ線をそのまま描く。隣り合う点は水平か垂直に並べる（斜めは validation エラー） |

ふつうは `layout` を書かなくてよい（全部既定値）。自動配線の形が気に入らないときだけ、部品の位置を直すか `routes` を使う。

## 2. 座標と部品の大きさ

- 単位はボードの px。原点は左上、x は右、y は下が正。
- `position` は**回転後の外接ボックスの左上**。**10 の倍数**にする（画面では 10 に丸められる）。
- ボードの基準サイズは **960 × 560**。部品・ラベル・ガイド線・GND 記号をすべてこの中に収める。
- 部品の外接ボックス: 横置き（`rotation` 0 / 180）は **72 × 39**、縦置き（90 / 270）は **39 × 72**。
- `rotation` は時計回り。90° にすると 1 番目のピンが上、2 番目のピンが下に来る（270° はその逆）。
  - 例: `V_DC`（ピン順 `p`, `n`）を 90° にすると `+` 側（`p`）が上。

### よく使う部品のピン位置（`position` からのずれ）

| 部品 | 向き | ピン（components.json の pinNames 順） |
|---|---|---|
| 2 端子（R, C, L, V_DC, V_AC, D, LED など） | 0° | 左 (0, 19.5) / 右 (72, 19.5) |
| 〃 | 90° | 上 (19.5, 0) / 下 (19.5, 72) |
| 〃 | 270° | 下 (19.5, 72) / 上 (19.5, 0) |
| 〃 | 180° | 右 (72, 19.5) / 左 (0, 19.5) |
| TP（テストポイント） | 0° | 下中央 (36, 39)。丸は上寄り、ID は丸の右 |
| GND | 0° | 上中央 (36, 0) |
| BJT / MOSFET / JFET（C/D, B/G, E/S） | 0° | 上 (43.5, 0) / 左 (0, 19.5) / 下 (43.5, 39) |
| 論理ゲート（A, B, Y） | 0° | 左上 (0, 12) / 左下 (0, 27) / 右 (72, 19.5) |
| OPAMP（in+, in−, out, V+, V−） | 0° | (0, 12) / (0, 27) / (72, 19.5) / (36, 0) / (36, 39) |
| DFF（4 端子） | 0° | 左 (0, 12), (0, 27) / 右 (72, 12), (72, 27) |
| 3 入力ゲート（U_AND3, U_OR3: A, B, C, Y） | 0° | 左 (0, 7.5) / (0, 19.5) / (0, 31.5) / 右 (72, 19.5) |
| U_XNOR（A, B, Y） | 0° | 2 入力ゲートと同じ（左 (0, 12) / (0, 27)、右 (72, 19.5)） |
| DFF_R（D, CLK, CLR, Q, Q_NOT） | 0° | 左 (0, 12) / (0, 27)、下中央 (36, 39) = CLR、右 (72, 12) / (72, 27) |
| LOGIC_IN（論理入力。Y の 1 ピン） | 0° | 右 (72, 19.5)。ID は記号の上。値の 0/1 は記号の中に表示（回転しても正立）。値ラベルは出さない |

ほかの部品は `src/ui/symbols.js` の `pins`（96 × 52 の設計座標）に 0.75 を掛けた値です。

DFF_R は CLR ピンが**下**に出るので、DFF_R の真下には 30px 以上の空きを残す（ピン名ラベル `CLR:…` は下ピンのラベル＝ピンの右下）。
LOGIC_IN は画面でクリックすると 0/1 が切り替わる（シミュレーションで試すため。固定部品でも可。チェックでは判定が自動で値を与える）。

**線をまっすぐにするコツ**: 向かい合うピンの座標をそろえる（`position` は 10 の倍数なので、そろうかどうかは下の端数で決まる）。

- 横置き 2 端子どうしを横一列に並べる → 同じ `y` にすればピンの y（`y + 19.5`）がそろい、まっすぐ結ばれる。
- 縦置き 2 端子どうしを縦一列に並べる → 同じ `x` にすればピンの x（`x + 19.5`）がそろう。
- TP のピン x は `x + 36`（端数 6）、縦置き 2 端子のピン x は端数 9.5 なので、**TP を縦置き部品の真上・真下に置くと必ず数 px の段ができる**。
  TP は結びたい線の**横（斜め上）**に置き、下向きのピンから線へ T 字で下ろすとよい。
- 横置き部品のピン（横向き）と縦置き部品のピン（縦向き）は L 字で結ばれるので、座標をそろえる必要はない。

## 3. ガイド線（固定配線の表示）

- **同じネット名を持つ固定部品のピンどうし**を、水平・垂直の線（薄い灰色）で結んで描く。
  プレイヤーが引くワイヤ（水色）とは別の見た目。
- **描画専用**です。電気的なつながりはこれまでどおりネット名（`connect`）で決まる。ガイド線は state の wires に入らない。
- 経路は自動で決まる:
  - 各ピンからまず外向きに 12px まっすぐ出し、そこから格子（10px）上を探索する。
  - 部品の外接ボックス（4px 広げたもの）と GND 記号は**通らない**。
  - 折れ曲がりが少なく、ラベルの上を通らず、他ネットの線と交差しない経路を優先する。
  - 他ネットの線と同じ向きに重なる（並走する）ことはない。交差は直角に横切るときだけ（交点では曲がらない）。
  - 3 本以上が集まる点（T 字の分岐）には黒丸を描く。
  - 経路が見つからないときは黄色の破線で代わりの線を描き、check_layout が `[d]` で報告する。
- プレイヤーが置いた部品はガイド線の対象外（プレイヤーは自分でワイヤを引く）。
- 固定部品をプレイヤーがドラッグで動かすと、ガイド線は引き直される。

### gnd ネットの扱い

- ネット名 `gnd`（または `0`）につながるピンは**線で結ばず**、各ピンのそばに **GND 記号を自動で描く**（ピンから外向きに 8px の線 + 横棒 3 本）。
  そのピンのピン名ラベル（`n:gnd` など）は表示しない。
- 配線モードでは、その GND 記号をクリックするとそのピン（＝ gnd）へ配線できる。
  そのため **固定の GND 部品（type `GND`）は通常不要**。置くと浮いた GND 記号に見えるので、新しい問題では置かない
  （check_layout が `[注意]` として知らせる。終了コードには影響しない）。
- `layout.groundSymbols: false` にすると、gnd もほかのネットと同じく線で結ぶ（グランドの共通線を見せたい問題向け）。

## 4. ラベルの位置（部品ごとに自動で決まる）

ラベルは部品の向きとピンの位置だけで決まり、ほかの部品には合わせて動かない。**ラベルの分の空きを残して部品を置く**こと。

- **ピン名ラベル**（固定部品は `ピン名:ネット名`、例 `p:vin`）: ピンから出る線の横に置く。
  左ピン → ピンの左上、右ピン → 右上、上ピン → ピンの右上、下ピン → ピンの右下。
- **ID ラベル**（例 `R1 🔒`）と**値ラベル**（例 `R=1kΩ`）:
  - 横置き: ID は部品の上、値は下（部品の中央そろえ）。
  - 縦置き: ID と値を部品の**右**に縦に並べる（右にピンがあれば左、それも無理なら上下）。
  - TP: ID は丸の右。トランジスタ（0°）: ID は左上、値は左下。
- 値ラベルは先頭 2 パラメータまで、22 文字を超えるときは後ろのパラメータを省く（値の途中では切らない）。
- 目安の大きさ: ID ラベル 1 文字 ≈ 7〜8px（高さ 12px）、値・ピン名ラベル 1 文字 ≈ 4〜5px（高さ 8〜9px）。
  縦置き部品の右には **ID の幅＋余白で 60px 程度**、横置き部品の上下には **15px 程度**の空きを残す。

## 5. 配置の目安

- 信号は左 → 右、電源（vin, vcc）は上、gnd は下。電源 V1 は左端に縦置き（`rotation: 90`）が基本。
- 部品どうしは外接ボックスの間で **30px 以上**離す（ピンから 12px の引き出し線と、線どうしの間隔のため）。
- 判定ノードの TP は、そのノードの線の近くに置き、ピン（下向き）から線へ短く下ろせる位置にする。
- 交差が多くなるときは部品の並べ方を変える。どうしても形が悪いときだけ `layout.routes` を使う。

## 6. 検査ツール

```
node tools/check_layout.mjs            # 全問題
node tools/check_layout.mjs A          # 分野 A（問題 ID の先頭一致: A-0, B-12 など）
node tools/check_layout.mjs --self-test
```

問題が 1 件でもあれば終了コード 1。検出する内容:

| コード | 内容 | 直し方 |
|---|---|---|
| `[a]` | 部品どうし（または自動 GND 記号と部品）の外接ボックスの重なり | 部品を 30px 以上離す |
| `[b]` | ボード 960 × 560 の外へのはみ出し（部品・ラベル・ガイド線・GND 記号）、`position` の指定漏れ、10 の倍数でない `position` | 内側へ移す / 10 の倍数にする |
| `[c]` | ラベルの重なり（ID / 値 / ピン名ラベルどうし、ラベルと他の部品、ラベルと GND 記号、ラベルとガイド線） | ラベルの分の空きを作る（4 章） |
| `[d]` | ガイド線が部品の本体を横切る / 経路が見つからない（ピンの出口がふさがれているなど） | ピンの外側を空ける、部品を動かす、`routes` を見直す |

ラベル幅は文字数からの見積もり（実際より少し大きめ）なので、ぎりぎりの配置は避ける。
新しい問題・配置を直した問題は、`node tools/verify.mjs` と合わせて `node tools/check_layout.mjs` も通すこと。
